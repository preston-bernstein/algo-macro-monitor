## Notes for /spec-challenge and /new-story
- This spec's working assumption is that implementation code lives in a NEW sibling repo
  (`~/dev/internal-monitor-service`, tentative name, confirmed unclaimed), following the `~/dev/internal-corpus-service`
  precedent. The spec itself (`docs/macro-context-monitor/`) lives inside internal-research-service for discoverability.
- Load-bearing non-negotiable: this tool NEVER makes or influences a live trading decision (FR-12).
  Verify this holds in every challenge pass — it is the single most important property of the design.
- Relevant `docs/DECISIONS.md` precedents this spec must stay distinguishable from: "Social-media/NLP
  sentiment momentum overlay — killed pre-spec (2026-07-04)", "Trade-policy/tariff-announcement-driven
  sector rotation — killed pre-spec (2026-07-04)", "Open-ended discovery pass: arXiv q-fin + GitHub
  trending — no actionable candidate found (2026-07-04)" (the "one-person LLM hedge fund" exclusion).
- `paper.db` schema and read path (confirmed live, 2026-07-04): `/home/internal-research-service/app/data/paper.db`
  on `desktop.example.internal`, tables `marks(date,symbol,price)`, `targets(date,strategy,symbol,weight,units,
  notional,fill_quality)`, `gate_results(run_date,strategy,passed,sharpe,sr_oos,mintrl,dsr,pbo,
  mc_prob_profit,reasons)` — note `gate_results` uses `run_date`, not `date`. Read via
  `ssh desktop.example.internal "sudo -n python3 -c \"import sqlite3; ...\""` (no `sqlite3` CLI on desktop; DB not
  world-readable).
- Data-source fetchability tested live this session: WebFetch fails on `reddit.com`/`old.reddit.com`
  AND `reuters.com`/`feeds.reuters.com` (broad anti-bot block, not reddit-specific). WebFetch succeeds
  on Fed press RSS, WSJ Markets RSS, Yahoo Finance RSS, `policyuncertainty.com`. WebSearch (distinct tool)
  works and is the correct path for message-board-flavored queries.
